## Findings (looked wrong — NOT fixed, report only)

- **F1 — Hero/search query never reaches the API (state race).** Captured request body for a hero search of "Inception": `note:""`, mood falls back to `Relaxed`/`Surprise me`. Every search (correct title, typo, non-English, gibberish, "movies like X") produced the *same generic pick set* (first card identical). Root cause pattern: `App.tsx` builds the request from the stale `wizardState` after async `setWizardState(...)`, so `note`, chips and reference movies are lost. Consequence: typo tolerance and title matching cannot be evaluated end-to-end (they were judged on the API surface earlier, not via this UI path).
- **F2 — Two-step search UX.** In natural/text mode, the first Enter on the hero input only opens a dedicated search page (no API call, page shows only a search box); the search only fires when the user presses Enter a *second* time there (or clicks submit). Users typing once and pressing Enter see an endless "Finding your picks…" splash — observed for ~60+s during the first (unfixed) probe run (screenshot `s03-inception-fail`).
- **F3 — Reference anchor fails live.** "movies like The Matrix" gets the honest notice "Couldn't load The Matrix for similarity matching" — the reference pipeline can't resolve the anchor in production.
- **F4 — Type:Series filter is a no-op.** Drawer state + chip show Series selected and a new 200 request fires, but the result set is unchanged (Totoro, a movie, stays first). Request sends `types:["Series"]` — capitalized value, which the server appears to ignore/normalize (lowercase `movie` from other flows works). Suggests an enum mismatch client→server.
- **F5 — Accessibility on the natural-search page.** Input lacks an accessible name (`serious/label-title-only`) and the page has no H1 (`moderate/page-has-heading-one`). Home and results pages are clean.
- **F6 — "Rating not confirmed" badges everywhere.** All cards show a "Rating not confirmed" chip next to a TMDB rating — ingest `certificate`/rating-confirmation data is missing at scale (pre-existing gate notices in server logs, e.g. "[gate] unknown certificate for …", match this).
